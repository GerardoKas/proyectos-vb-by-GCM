Console Apps

It's almost trivial to create console applications in VB.

There are only two things you need to create a Console app in VB:
1) The necessary support code to read or write to the console.
2) The EXE must be compiled as a Console Subsystem application.

Requirement #1, support code:

All that is required to write text to the console is two API calls:

Private Declare Function GetStdOutHandle Lib "kernel32" _
        Alias "GetStdHandle" _
       (Optional ByVal HandleType As Long = -11) As Long

Private Declare Function WriteFile Lib "kernel32" _
       (ByVal hFile As Long, _
        ByVal lpBuffer As String, _
        ByVal cToWrite As Long, _
        ByRef cWritten As Long, _
        Optional ByVal lpOverlapped As Long) As Long

To keep things simple, wrap these two APIs in a single helper function like so:

Private Function ConsoleWrite(sText As String) As Long
    WriteFile GetStdOutHandle, ByVal sText, Len(sText), ConsoleWrite
End Function

And now all you need to do is call your helper function when you want to write to the console:
Private Sub Main()
    ConsoleWrite "Hello Console World!"
End Sub

If all you need to do is output a bit of text to the console, then the above code will suffice. However, if you need more advanced capabilities, like detecting Ctrl-C keypresses and system shutdown, or retrieving piped input, then the code involved gets a lot more complicated.

Fortunately, we have a remarkable new Console support BAS module courtesy of Karl E. Peterson (http://www.mvps.org/vb/) included in the vbAdvance download. This module is the most comprehensive console support code available. Housed in a single BAS module, this code provides full support for debugging console apps from within the VB IDE, provides control handler callback notification for things like Ctrl-C keypresses, allows you to capture piped input, allows you to determine if your app was started from a console session or from Explorer, allows you to read from and write to the console, change colors, control cursor positioning, set window visibility, width and height, and more.

This module is included with the samples installed with vbAdvance. You can also pick up the latest copy of this code directly from Karl's website:
http://www.mvps.org/vb/code/Console.zip

Requirement #2, the Console Subsystem switch:

The second requirement is that the app be compiled as a Console subsystem
application. VB has the ability to do this, but doesn't give you a way to enable the
feature. This is where vbAdvance comes in. Simply check the "Build As Console
Application" checkbox and vbAdvance will tell VB at compile time that your app is
to be compiled as a Console subsystem application. (Remember, vbAdvance is
free for use in creating console applications!)

Even though vbAdvance makes it incredibly easy to build Console apps, and even though this is a freebie feature and wouldn't cost you a thing, some people might prefer to control the build step themselves. In this case, all you need to do is call the VB linker after you build your EXE. The VB linker is capable of altering your compiled EXE so that it is a true console subsystem application. The usage looks like so:
link /edit /subsystem:console myapp.exe

Again, this is a seperate build step and is not required if you use vbAdvance.

There are many other utilities out there that accomplish the same thing. vbAdvance
makes it painless by building the feature into the VB IDE, so building a Console app is as simple as building a Windows app. Once your project is marked as a Console app, it will always compile as a Console subsystem app, because vbAdvance remembers the project setting automatically.
